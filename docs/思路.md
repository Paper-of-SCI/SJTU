# 语义 / Patch 引导的 3DGS Densification 思路

## 1. 核心想法

这个方法的核心不是给 3DGS 额外加一个语义输出，也不是把 semantic mask 当作 RGB 监督标签，而是用图像 patch 级别的先验去控制 3DGS 原本的 densification。

原版 3DGS 的 densification 主要看 Gaussian 的屏幕空间梯度。梯度大，说明这个 Gaussian 投影到图像上时对 loss 比较敏感，于是更可能 clone 或 split。这个机制有效，但它只知道“哪里优化压力大”，不知道这个区域是不是细节丰富、是不是语义上重要、是不是应该保留更多 Gaussian budget。

这里的思路是：

```text
当前渲染误差 + 图像边缘复杂度 + 可选语义重要性
  -> 构造 patch-level detail score
  -> 投影回可见 Gaussian
  -> 调整每个 Gaussian 的 densification score
  -> 高价值区域更容易 clone / split
  -> 低价值区域可被 prune / reallocate
```

最终目标是让有限的 Gaussian 数量更多分配到高误差、高细节、高语义价值区域，而不是平均地、盲目地增长。

当前方法只改 densification，不改 RGB renderer，不改 photometric loss，不引入 semantic feature rendering。也就是说，它改变的是 3D 表示的容量分布，而不是直接改变颜色渲染公式。

## 2. 当前消融设计

为了区分每个因素的贡献，当前实验分成 5 个 variant：

```text
standard_3dgs
  = 原版 screen-space gradient densification

patch_guided
  = error + edge

patch_guided_semantic
  = error + edge + semantic

patch_reallocate
  = error + edge + reallocate

patch_reallocate_semantic
  = error + edge + semantic + reallocate
```

这里必须注意：

```text
patch_reallocate 不读取 semantic mask。
patch_reallocate_semantic 才读取 semantic mask。
```

这样做的原因是消融更清楚。如果直接让 `patch_reallocate` 自动带 semantic，那么 reallocation 的收益和 semantic 的收益会混在一起，后面很难解释。

## 3. 模块边界

这个方法涉及三个主要边界。

### 训练入口

Owner：`methods/3dgs/train_3dgs_scene.py`

责任：

```text
1. 读取数据集和相机。
2. 构造 GaussianModel、renderer、optimizer。
3. 根据 --densification-mode 选择 densifier。
4. 如果当前 variant 需要 semantic，则读取当前图像对应的 semantic_importance mask。
5. 每一步训练后调用 densifier.update(...)。
6. 周期性评估 held-out view，并保存 best checkpoint。
```

输入：

```text
data scene
训练参数
densification mode
可选 semantic_importance_root
```

输出：

```text
final.ply
checkpoints/*.ply
best/best_psnr.ply
best/best_ssim.ply
best/best_lpips.ply
training_summary.json
best_metrics.json
```

### Densification 算法

Owner：`modules/densification.py`

责任：

```text
1. 根据 render image、GT image 计算 patch_detail。
2. 把 patch_detail 投影累计到 Gaussian。
3. 用 avg_detail 调整 screen-space gradient。
4. 生成 clone / split / prune / reallocate mask。
5. 修改 Gaussian 参数，并同步 optimizer state。
```

输入是窄接口：

```text
model
render_output
optimizer
step
gt_image
optional semantic_importance
```

输出是窄接口：

```text
DensificationStats
```

它不读文件、不解析命令行、不知道数据集路径，也不生成 semantic mask。

### Semantic mask 读取

Owner：`methods/semantic_importance.py`

责任：

```text
按当前训练图像名读取对应灰度 mask。
如果尺寸不匹配，则 resize 到当前训练分辨率。
输出 HW tensor，范围 [0, 1]。
```

路径约定：

```text
semantic_importance/<scene_name>/<image_stem>.png
```

如果 semantic variant 缺少 mask，应该直接报错，而不是静默退化成无语义版本。

## 4. 原版 3DGS Densification

原版 3DGS 会累计每个 Gaussian 的 screen-space position gradient。记第 `i` 个 Gaussian 的平均梯度为：

```text
g_i = gradient_accum_i / max(gradient_count_i, 1)
```

这里的梯度要特别区分清楚。训练优化时，Gaussian 的所有可学习参数都会有梯度，例如：

```text
3D position means_i
scale_i
rotation_i
opacity_i
SH color_i
```

但是 densification 用来判断 `high_grad_i` 的，通常不是直接取所有属性梯度，也不是直接取 3D `means_i` 的梯度，而是取 Gaussian 投影到图像平面后的 2D 屏幕空间位置梯度。记第 `i` 个 Gaussian 的 3D 位置为：

```text
mu_i^{3D} = (x_i, y_i, z_i)
```

经过当前相机投影后得到屏幕空间位置：

```text
mu_{i,v}^{2D} = Pi_v(mu_i^{3D}) = (u_{i,v}, v_{i,v})
```

图像重建 loss 为：

```text
L_v = loss(I_hat_v, I_v)
```

则 densification 使用的梯度可以理解为：

```text
g_{i,v} = || partial L_v / partial mu_{i,v}^{2D} ||
```

多次可见视角累计后得到平均梯度：

```text
g_i = mean_v(g_{i,v})
```

这个梯度的直觉是：

```text
如果某个 Gaussian 在图像平面上稍微移动就会明显改变 loss，
说明它附近的重建还不稳定，可能需要更多 Gaussian 表达。
```

反向传播时，2D 投影位置梯度仍然会通过投影链路传回 3D 位置：

```text
partial L / partial mu_i^{3D}
  =
partial L / partial mu_i^{2D}
  *
partial mu_i^{2D} / partial mu_i^{3D}
```

所以可以概括为：

```text
optimizer 更新的是 3D Gaussian 参数；
densification 判断主要看 screen-space 2D position gradient。
```

然后用一个阈值判断它是否需要 densify：

```text
high_grad_i = g_i >= tau
```

其中：

```text
tau = densify_grad_threshold
```

clone / split 的选择由 Gaussian 尺度决定。记：

```text
s_i = max(scale_i)
t_dense = scene_extent * percent_dense
```

则：

```text
clone_i = high_grad_i and s_i <= t_dense
split_i = high_grad_i and s_i >  t_dense
```

低 opacity 或屏幕半径过大的 Gaussian 会被 prune：

```text
prune_i = opacity_i < min_opacity
```

如果启用了 `max_screen_radius`，则还会加上：

```text
prune_i = prune_i or radius_i > max_screen_radius
```

原版逻辑的问题是：它只看梯度，不知道这个 Gaussian 经常落在哪种图像区域。水下场景里有很多低纹理水体、悬浮噪声、背景雾化区域，这些区域不一定应该占用太多 Gaussian。

## 5. Patch Detail 的定义

每次训练选中一个视角 `v`，renderer 输出当前渲染图：

```text
I_hat_v in R^{3 x H x W}
```

GT 图像为：

```text
I_v in R^{3 x H x W}
```

图像被划分成 patch。当前实验常用：

```text
patch_size = 32
```

第 `p` 个 patch 的像素集合记为：

```text
Omega_p
```

### 5.1 Patch Error

先计算每个像素的 RGB 平均绝对误差：

```text
e_v(x, y) = (1 / 3) * sum_c |I_hat_v(c, x, y) - I_v(c, x, y)|
```

再对 patch 做平均池化：

```text
E_{p,v} = (1 / |Omega_p|) * sum_{(x,y) in Omega_p} e_v(x, y)
```

`E_{p,v}` 表示当前 patch 的重建误差。误差越大，说明当前模型在这个局部区域拟合得越不好。

### 5.2 Patch Edge

边缘强度从 GT 图像计算，而不是从 render 图像计算。原因是我们希望 densification 更关注真实结构边界，而不是当前模型已经渲染出来的模糊边界。

先把 GT 图像转成灰度：

```text
G_v(x, y) = (1 / 3) * sum_c I_v(c, x, y)
```

用 Sobel 核计算梯度：

```text
S_x = K_x * G_v
S_y = K_y * G_v
```

其中：

```text
K_x =
[[ 1,  0, -1],
 [ 2,  0, -2],
 [ 1,  0, -1]]

K_y =
[[ 1,  2,  1],
 [ 0,  0,  0],
 [-1, -2, -1]]
```

像素边缘强度为：

```text
a_v(x, y) = sqrt(S_x(x, y)^2 + S_y(x, y)^2)
```

patch 边缘强度为：

```text
A_{p,v} = (1 / |Omega_p|) * sum_{(x,y) in Omega_p} a_v(x, y)
```

`A_{p,v}` 越大，说明 patch 内真实结构越复杂。

### 5.3 Min-Max Normalize

为了让 error 和 edge 在同一尺度上组合，对每个视角的 patch map 做 min-max normalize：

```text
N(X_p) = (X_p - min_q X_q) / max(max_q X_q - min_q X_q, eps)
```

这里的 `min_q` 和 `max_q` 是在**当前训练视角的所有 patch** 上取的，不是全数据集统一统计。也就是说，每张训练图都会独立归一化：

```text
{X_1, X_2, ..., X_P}  ->  当前图像全部 patch 的分数
```

归一化表达的是：

```text
在当前这张训练图里，哪些 patch 相对更重要。
```

如果所有 patch 的值几乎相同，则归一化结果设为 0，避免除零和随机放大。

记：

```text
E_tilde_{p,v} = N(E_{p,v})
A_tilde_{p,v} = N(A_{p,v})
```

### 5.4 Error + Edge Detail

基础 patch detail 为：

```text
D_base_{p,v}
  = N( E_tilde_{p,v} * (1 + alpha * A_tilde_{p,v}) )
```

其中：

```text
alpha = patch_edge_weight
```

当前常用：

```text
alpha = 0.75
```

直观理解：

```text
重建误差大 -> detail 高
真实边缘强 -> detail 进一步放大
```

只使用这部分时，就是 `patch_guided`。

## 6. Semantic Importance

语义重要性是一个每张训练图对应的灰度 mask：

```text
M_v in [0, 1]^{H x W}
```

它不是 GT label，不参与 RGB loss，只用于改变 patch_detail。

对 mask 做 patch 平均：

```text
S_{p,v} = (1 / |Omega_p|) * sum_{(x,y) in Omega_p} M_v(x, y)
```

然后构造 semantic factor：

```text
F_{p,v} = beta + (1 - beta) * S_{p,v}
```

其中：

```text
beta = semantic_base
```

当前常用：

```text
beta = 0.2
```

含义：

```text
S_{p,v} = 0   -> F_{p,v} = 0.2
S_{p,v} = 0.5 -> F_{p,v} = 0.6
S_{p,v} = 1   -> F_{p,v} = 1.0
```

最终 semantic 版本的 patch detail：

```text
D_{p,v} = D_base_{p,v} * F_{p,v}
```

注意：当前实现中，乘 semantic factor 之后不再重新 min-max normalize。这样做是有意的，因为语义低的 patch 会被真正压低，而不是又被 normalize 拉回去。

不带 semantic 的版本就是：

```text
D_{p,v} = D_base_{p,v}
```

## 7. Patch Detail 如何分配给 Gaussian

每个训练 step，renderer 会返回每个可见 Gaussian 的屏幕空间投影位置：

```text
m_{i,v} = (x_{i,v}, y_{i,v})
```

如果该点在图像范围内，并且 Gaussian 在当前视角可见，则根据投影位置找到 patch：

```text
u_{i,v} = floor(x_{i,v} / patch_size)
w_{i,v} = floor(y_{i,v} / patch_size)
p(i, v) = (w_{i,v}, u_{i,v})
```

然后累计：

```text
detail_accum_i += D_{p(i,v), v}
detail_count_i += 1
```

到 densification 触发时，得到每个 Gaussian 的平均 detail：

```text
q_i = detail_accum_i / max(detail_count_i, 1)
```

其中：

```text
q_i in [0, 1]
```

直观理解：

```text
一个 Gaussian 如果经常投影到高误差、高边缘、高语义重要性的 patch，
它的 q_i 就会变大。
```

当前实现用的是 Gaussian 投影中心所在 patch。更精细的后续版本可以使用 alpha contribution 加权：

```text
q_i =
  sum_{v,p} w_{i,p,v} * D_{p,v}
  / max(sum_{v,p} w_{i,p,v}, eps)
```

其中 `w_{i,p,v}` 表示第 `i` 个 Gaussian 在视角 `v`、patch `p` 的渲染贡献。这个版本更准确，但需要 renderer 暴露更细的 per-Gaussian contribution。

## 8. 用 Patch Detail 调整 Densification

原版 3DGS 用：

```text
g_i >= tau
```

当前方法不直接废掉原版梯度，而是用 patch detail 构造一个有界增强因子来放大梯度：

```text
d_i = q_i
w_i = 1 + lambda_detail * d_i
g_adjusted_i = g_i * w_i
```

其中：

```text
lambda_detail = patch_detail_lambda
d_i = 第 i 个 Gaussian 的平均 patch detail
```

当前常用：

```text
lambda_detail = 2.0
```

因为：

```text
d_i in [0, 1]
```

所以最终真正乘到梯度上的不是 `[0, 1]` 的 `d_i`，而是：

```text
w_i = 1 + lambda_detail * d_i
```

在当前设置下：

```text
w_i in [1, 3]
```

也就是说：

```text
d_i = 0 -> w_i = 1，梯度不变
d_i = 1 -> w_i = 3，梯度最多放大 3 倍
```

这点很重要。如果直接用：

```text
g_i * d_i
```

由于 `d_i <= 1`，反而会让所有 Gaussian 更难超过阈值，相当于整体提高阈值。当前实现使用 `1 + lambda_detail * d_i`，因此不会整体压低 densification，只会让高 detail 区域更容易被选中。

然后判断：

```text
high_grad_i = g_adjusted_i >= tau
```

把它改写成局部阈值形式：

```text
g_i * w_i >= tau
```

等价于：

```text
g_i >= tau / w_i
```

因此：

```text
d_i 越大 -> w_i 越大 -> tau / w_i 越小
```

也就是：

```text
高 error / 高 edge / 高 semantic 区域会有更低的有效 densification 阈值。
低 detail 区域在 d_i = 0 时保持原版阈值，不会被额外鼓励 densify。
```

这样有两个好处：

```text
1. 仍然保留原版 3DGS 的主路径，不会完全靠 patch 规则强行加球。
2. 同样梯度下，高 detail 区域的 Gaussian 更容易超过阈值。
```

clone / split 的选择当前仍然用原版尺度规则。也就是说，本方法主要解决：

```text
哪些 Gaussian 更应该被选中 densify。
```

一旦 Gaussian 被选中，具体是 clone 还是 split，仍然看它自己的尺度：

```text
clone_i = high_grad_i and s_i <= t_dense and not prune_i
split_i = high_grad_i and s_i >  t_dense and not prune_i
```

其中：

```text
s_i = max(scale_i)
t_dense = scene_extent * percent_dense
```

直觉是：

```text
小 Gaussian 不够用 -> clone，复制更多局部小点。
大 Gaussian 太粗糙 -> split，拆成更小的 Gaussian。
```

这对应 `patch_guided` 和 `patch_guided_semantic` 的核心逻辑。

后续如果要进一步改进，可以把 `d_i` 也引入 clone/split 的分界阈值。例如：

```text
t_i = t_dense / (1 + alpha_split * d_i)
```

再用：

```text
clone_i = high_grad_i and s_i <= t_i
split_i = high_grad_i and s_i >  t_i
```

这样高细节区域的阈值更低，较大的 Gaussian 更容易 split。但这属于额外设计，当前主实验没有启用，避免和现有 patch/semantic 消融混在一起。

## 9. Clone 和 Split 的新 Gaussian 怎么生成

### 9.1 Jittered Clone

普通 clone 会完全复制父 Gaussian，容易重合。当前 patch-guided 路径使用 jittered clone：

```text
mu_child = mu_parent + R_parent * epsilon
```

其中：

```text
epsilon ~ Normal(0, (eta * scale_parent)^2)
eta = clone_jitter_scale
```

当前常用：

```text
eta = 0.05
```

其他参数复制父 Gaussian：

```text
scale_child   = scale_parent
quat_child    = quat_parent
opacity_child = opacity_parent
color_child   = color_parent
```

### 9.2 Split

对于尺度较大的 Gaussian，使用 split：

```text
mu_child_k = mu_parent + R_parent * delta_k
delta_k ~ Normal(0, scale_parent^2)
```

scale 缩小：

```text
log_scale_child = log_scale_parent - log(scale_shrink)
```

当前：

```text
scale_shrink = 1.6
num_splits = 2
```

也就是说，一个 split parent 会生成多个更小的 child，用来表达局部细节。

## 10. Reallocation 思路

普通 densification 主要是“哪里需要就加哪里”，但它没有明确把低价值区域的 Gaussian budget 转移出来。`patch_reallocate` 和 `patch_reallocate_semantic` 额外做这件事。

### 10.1 Reallocation Budget

每次 densification 触发时，先计算最多要重分配多少 Gaussian：

```text
B = round(N * rho)
```

其中：

```text
N   = 当前 Gaussian 数量
rho = reallocate_fraction
```

当前命令里：

```text
rho = 0.10
```

这比较激进。诊断实验可以用：

```text
rho = 0.005 或 0.01
```

候选集合排除已经要 clone、split 或 prune 的 Gaussian：

```text
C = not clone_mask and not split_mask and not prune_mask
B = min(B, |C|)
```

### 10.2 选低价值 Gaussian 做 Extra Prune

先归一化：

```text
q_tilde_i = N(q_i)
c_tilde_i = N(detail_count_i)
```

其中：

```text
q_i             = 平均 patch detail
detail_count_i  = 被可见视角累计到的次数
opacity_i       = 当前透明度
```

低价值分数：

```text
low_score_i =
    0.55 * (1 - q_tilde_i)
  + 0.20 * (1 - c_tilde_i)
  + 0.25 * (1 - opacity_i)
```

含义：

```text
低 detail       -> 更可能被删
低可见 / 少累计 -> 更可能被删
低 opacity      -> 更可能被删
```

从候选集合里取 top B：

```text
extra_prune = topK(low_score, C, B)
```

### 10.3 把 Budget 补到高价值区域

得到实际 prune 数量：

```text
B_realloc = |extra_prune|
```

高价值 source score：

```text
source_score_i = g_adjusted_i * (1 + q_i)
```

也就是说，同时考虑：

```text
当前优化梯度
patch detail
```

先尽量 clone 小 Gaussian：

```text
extra_clone = topK(
  source_score,
  source_candidate and s_i <= t_dense,
  B_realloc
)
```

如果 clone 没用完 budget，再对大 Gaussian 做 split：

```text
split_parent_budget = remaining / num_splits

extra_split = topK(
  source_score,
  source_candidate and s_i > t_dense,
  split_parent_budget
)
```

如果还剩预算，则 fallback 到 clone。

最终：

```text
prune_mask = prune_mask or extra_prune
clone_mask = (clone_mask or extra_clone) and not prune_mask
split_mask = (split_mask or extra_split) and not prune_mask
```

这就是 reallocation 的核心：不是简单增加 Gaussian，而是试图从低价值区域拿 budget，补给高价值区域。

## 11. 每个 Variant 具体做什么

### 11.1 `standard_3dgs`

只用原版梯度：

```text
g_i >= tau
```

不计算 patch_detail，不读取 semantic mask，不做 reallocation。

### 11.2 `patch_guided`

计算：

```text
D_{p,v} = N( N(E_{p,v}) * (1 + alpha * N(A_{p,v})) )
```

投影到 Gaussian 得到 `q_i`，再用：

```text
g_adjusted_i = g_i * (1 + lambda_detail * q_i)
```

它验证的是：只看 error + edge 的 patch-aware densification 是否有效。

### 11.3 `patch_guided_semantic`

在 `patch_guided` 基础上乘 semantic factor：

```text
D_{p,v} = D_base_{p,v} * (beta + (1 - beta) * S_{p,v})
```

它验证的是：semantic mask 是否能进一步改善 Gaussian budget 分配。

### 11.4 `patch_reallocate`

在 `patch_guided` 基础上启用 reallocation：

```text
error + edge + reallocate
```

它不读取 semantic mask。它验证的是：单独的 reallocation 机制有没有用。

### 11.5 `patch_reallocate_semantic`

在 `patch_guided_semantic` 基础上启用 reallocation：

```text
error + edge + semantic + reallocate
```

它验证的是：semantic 和 reallocation 结合后是否进一步提升。

## 12. 训练主流程

每一步训练流程：

```text
1. 随机选一个训练视角。
2. 用当前 GaussianModel render 当前视角。
3. 计算 RGB photometric loss：
     L = (1 - lambda_dssim) * L1 + lambda_dssim * DSSIM
4. loss.backward()
5. optimizer.step()
6. densifier.update(...)
7. 如果 step 到达 densify interval，则 clone / split / prune / reallocate。
8. 如果 step 到达 eval interval，则评估 held-out views 并保存 best checkpoint。
```

当前 RGB loss 是：

```text
L1 = mean(|I_hat - I|)
SSIM = ssim(I_hat, I)
DSSIM = (1 - SSIM) / 2
L = (1 - lambda_dssim) * L1 + lambda_dssim * DSSIM
```

当前：

```text
lambda_dssim = 0.2
```

注意：semantic mask 不进入这个 RGB loss。

## 13. 训练期 Best Checkpoint

只看最终 `final.ply` 有一个问题：训练过程中某个中间 step 可能测试指标更好，后面继续训练可能轻微过拟合或 Gaussian 数量膨胀。因此当前训练会周期性在 held-out test views 上评估。

评估间隔由 benchmark 参数控制：

```text

```

训练脚本收到后对应：

```text

```

每次评估计算：

```text
PSNR

```

如果 benchmark 传了：

```text

```

则训练期 best tracking 也计算 LPIPS，并沿用：

```text

```

best 规则：

```text

```

每个 run 会保存：

## 16. 风险和注意点

### 16.1 Semantic Mask 漏检

semantic mask 如果漏掉真实重要区域，会压低这些区域的 `D_{p,v}`。

缓解方式：

```text
semantic_base 不要设为 0。
当前 beta = 0.2，表示低语义区域仍保留 20% 权重。
```

### 16.2 Reallocation 过激

`reallocate_fraction=0.10` 表示每次 densification 最多拿当前 Gaussian 数量的 10% 做重分配。densification 每 100 步触发时，这个比例可能导致 Gaussian 数量增长很快。

如果出现：

```text
显存爆
训练速度明显变慢
Gaussian 数量几百万
PSNR 不升反降
```

优先尝试：

```text
--reallocate-fraction 0.005
```

或：

```text
--reallocate-fraction 0.01
```

### 16.3 下采样影响指标

不同分辨率和下采样方式会影响 PSNR、SSIM、LPIPS。当前实验统一用：

```text
--target-width 720
```

这样所有 variant 至少在同一套预处理下比较。不要把不同 resize 方式下的指标直接混在同一张表里。

### 16.4 Best Metrics 不等于主表结果

`best_psnr.ply`、`best_ssim.ply`、`best_lpips.ply` 是训练过程中不同指标各自最优的 checkpoint。它们可能来自不同 step。

所以写论文时要说清楚：

```text
final metrics：训练结束 final.ply 的指标。
best metrics：训练过程中 held-out evaluation 最优指标。
```

主表建议用 final metrics，best metrics 用来辅助分析。

## 18. 最终可写成论文方法的表述

可以把方法概括为：

```text
Patch-guided semantic-aware densification for underwater 3D Gaussian Splatting.
```

更完整一点：

```text
We construct a patch-level detail score from reconstruction error, image edge strength,
and optional semantic importance. The patch scores are accumulated onto visible
Gaussian primitives according to their screen-space projections. The accumulated
detail score modulates the standard 3DGS screen-space gradient used for densification,
making Gaussians projected to high-detail and semantically important regions more
likely to be cloned or split. We further study a reallocation variant that prunes
low-detail, low-opacity, and rarely visible Gaussians and reallocates the budget
to high-detail regions.
```

中文解释：

```text
我们不是让语义直接参与颜色渲染，而是让语义和 patch 细节影响 Gaussian 的数量分配。
这样方法的作用点在 3D 表示结构本身：哪些地方应该有更多 Gaussian，哪些地方可以减少 Gaussian。
```
